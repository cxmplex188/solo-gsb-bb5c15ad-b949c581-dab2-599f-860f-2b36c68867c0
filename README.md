# 情景注入台（桌面事故演练）

主持人编排带**相对触发秒数**的注入卡片并启动演练；服务端维护可**暂停/继续**的虚拟时钟，
按 `(触发秒数, 序号)` 稳定揭示卡片，暂停期间时钟冻结、绝不推进。
支持**分组定向注入**：主持人可管理 2～8 个参与组（每组一个独立加入码），卡片可投向
「全员」或指定参与组；参与者凭**组加入码**进入，只能看到全员卡片与目标为本组的卡片，
未命中的卡片在触发前后都不会通过 REST 或 WebSocket 下发。主持人始终看到全部卡片。
断线重连时先恢复权威快照，再按递增事件 ID 接收增量，状态不回退、不混入他组内容。

**卡片回执**：每张已揭示卡片，参与者可一键标记「已收到」，也可再次点击撤销；
同一参与组对同一卡片仅保留一条回执（重复标记幂等）。主持人卡片列表实时显示每组的
回执/未回执汇总——全员卡片统计所有参与组，定向卡片只统计目标组；回执状态持久化在
SQLite 中，断线重连、刷新或服务重启后均不丢失。未揭示的卡片不可回执。

**回执门槛**：主持人可让一张卡片依赖指定的前置卡片——前置卡片对其目标参与组
（全员卡 = 全部参与组，定向卡 = 目标组）全部集齐回执后，本卡才揭示；还可同时设置
**虚拟时钟超时秒数**（自本卡触发时刻起算），超时仍未集齐则标记为「**超时揭示**」并继续。
门槛计时走虚拟时钟：暂停期间冻结、重置后随回执清零重新等待；门槛配置、回执与
超时标记全部持久化，断线重连、刷新、服务重启后状态不丢。主持人在卡片上看到
「等待回执 / 已解锁 / 超时揭示」状态与未回执组名单；参与者与观察者不感知门槛编排，
仍只按现有视野收到已揭示卡片。

**处置答复**：每张已揭示卡片下，参与者可提交并反复修改**本组唯一一份答复**（同组多人
共享）。更新必须携带当前 `revision` 版本号，版本过期返回 `409` 并附带最新答复，
同组多窗口不会静默互相覆盖。主持人可**逐卡锁定 / 重新开放**答复：锁定后参与者只读，
写入返回 `409`。主持人在卡片上实时看到各应答组的**提交状态、正文与版本号**——
定向卡只统计目标组，全员卡覆盖现有全部参与组。答复持久化在 SQLite 中，经快照与
WebSocket 恢复；参与者只能看到本组答复，**看不到他组正文**，观察者完全拿不到答复。
「重置」清空全部答复并解除全部锁定，新一轮演练从零作答。

**限时观察席**：主持人可勾选 1～3 个参与组并设置 5～120 分钟有效期，一键生成
**可撤销的随机观察链接**。观察者是只读角色：只能通过 REST 与 WebSocket 收到
**已揭示**的全员卡片与所选组卡片，拿不到未揭示卡片、房间码、组加入码、回执明细，
也没有任何控制能力。服务端按观察凭证过滤快照与增量事件；**到期或主持人撤销时**
在线观察者被立即断开，此后 REST 一律返回 `410`、WebSocket 拒绝接入，刷新重连
也不能恢复权限。凭证与状态持久化在 SQLite 中，服务重启后仍然有效（或仍然失效）。

**现场决策投票**：主持人可发起含 **2～4 个选项**、**指定参与组**与**截止虚拟秒**
（相对本轮开始，1～86400 秒）的投票，截止点必须晚于当前虚拟时钟。只有指定参与组
能在**截止前**投票或改投，**每组只计一票**（同组任一人操作即全组生效，重复投票
原地更新，不增加票数）。后台 tick 与卡片揭示共用同一把 `state_lock`，在锁内对到期
投票**一次性结算**：**最高票获胜，平票按选项创建顺序**决定（全员零票时第一个选项
获胜），获胜选项与结算虚拟毫秒持久化到 SQLite。截止计时走虚拟时钟——**暂停即冻结**，
暂停期间仍可改投；重连、刷新与服务重启后状态恢复（重启先把运行中房间安全冻结为
已暂停），每条投票只结算一次，不会重复广播。主持人在投票卡片上**实时查看逐组选票**
（哪一组投了哪个选项、未投组名单）与选项汇总；参与者在**结算前只见自己的选择**，
看不到任何票数或他组选择，**结算后**才看到获胜选项与汇总票数（仍看不到逐组明细）；
观察者对投票**完全不可见**（快照不带、`poll_*` 事件不下发）。**重置时未结算投票
一律作废**（选票删除、状态置为已作废），**已结算结果按轮次保留**（归属创建轮次，
主持人可回看历史轮结果，新参与者视图不再出现旧轮投票）。

**复盘锚点**：主持人可在**任意房间状态**（开始前 / 运行中 / 暂停后 / 重置后）记录
带**标题与备注**的锚点。服务端在与所有写操作**同一把状态锁**内，按严格次序把锚点
绑定到**当前轮次**（= 此前重置事件数）、**当时事件水位**（锚点自身事件落库前的
`MAX(events.id)`）与**当前虚拟毫秒**（running 结算当前运行段，paused/idle 取冻结值，
**暂停期间时间冻结**）；锚点自身创建事件 id 恰为绑定水位 + 1。锚点支持**修改备注**
与**删除**，变化持久化在 SQLite 并经 WebSocket 实时同步给主持人；参与者与观察者
**完全不可见**（快照不带、`anchor_*` 事件不下发）。**重置不删锚点**——锚点跨轮次
保留并以行内轮次归属原轮次。导出复盘包时只包含**不晚于导出水位**（按锚点自身创建
事件 id 截断）的锚点；离线回放页**按轮次列出锚点**，点击后切到对应轮次、滑块跳到
绑定虚拟毫秒，并**仅重放至锚点绑定水位**——同一虚拟毫秒内 ID 更晚的事件不计入，
精确还原锚点时刻状态。

**复盘包导出**：主持人可在**任意时刻**（开始前 / 运行中 / 暂停后 / 重置后）一键导出
ZIP 复盘包。服务端在与所有写操作同一把锁内先读取**当前事件水位**（`events` 最大 ID），
随后只打包 `id <= 水位` 的事件与该时刻状态——生成期间到达的新事件**绝不混入**。
包内包含**房间编排、已揭示卡片、回执、答复版本轨迹、时钟动作**与脱敏事件流，并自带
**无需联网即可打开**的单文件回放页 `replay.html`：可选择演练轮次、拖动**虚拟时间**
滑块还原当时状态（支持按 1×/4×/20×/60× 播放），同一虚拟时刻的事件严格按**事件 ID**
稳定排序，每张卡片可展开查看各组答复的完整历史版本。导出内容已**剔除房间码、组加入码
与观察 token**（观察分享事件整类不导出）；**空演练**（无组、无卡、未开始）也能导出
并正常打开。

技术栈：FastAPI + SQLite + 原生 HTML/JS（WebSocket 实时推送）。

## 启动（一条命令）

```bash
docker compose up --build
```

启动后访问：

- **Web 地址：** http://localhost:8000
- **端口：** `8000`（宿主机端口可在 `docker-compose.yml` 的 `ports` 中修改）

依赖安装、SQLite 建表与**旧库就地迁移**（补回执门槛、处置答复、复盘锚点、现场决策
投票等新列/新表）均已纳入启动流程，无需额外初始化步骤；数据持久化在命名卷
`inject-data` 中。

## 配置（环境变量，可在 docker-compose.yml 的 `environment` 中调整）

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `DATABASE_PATH` | `/data/inject.db` | SQLite 数据库文件路径 |
| `TICK_INTERVAL` | `0.25` | 服务端揭示扫描周期（秒） |

## 使用流程

1. **主持人**：打开首页 →「创建演练」→ 在控制台**创建参与组**（2～8 个，每组自动生成
   6 位加入码，可随时改名；已被卡片引用的组不可删除）→ 添加注入卡片时为每张卡片选择
   目标（**全员**或某个参与组），可选设置**回执门槛**（前置卡片 + 虚拟时钟超时秒数）
   →「开始演练」。
   时钟运行中可「暂停 / 继续」，「重置」将时钟归零并收回全部已揭示卡片，
   但**保留参与组、加入码、卡片目标与门槛编排**。运行期间不可编辑卡片（需先暂停），保证揭示次序稳定。
2. **参与者**：首页输入主持人分享的 6 位**组加入码** → 实时看到本组可见的已揭示卡片与演练时钟。
   未触发、或未投向本组的卡片对参与者不可见；卡片上的「全员 / 仅 ×组」徽标标明其目标。
   每张已揭示卡片上有「**标记已收到**」按钮，点击即回执（同组只需一人操作，全组生效），
   再次点击可撤销；回执状态断线重连后自动恢复。
   卡片下方可填写**本组处置答复**：每组一份、同组共享，可反复修改（每次保存版本号 +1）；
   若同组其他窗口已先保存，本窗口会收到冲突提示并自动载入最新版本，不会静默覆盖。
   主持人锁定后答复区变为只读。
3. **回执汇总**：主持人在每张已揭示卡片下方看到「回执 n/m」与逐组徽标
   （✓ 已回执 / 未回执），随参与者的标记与撤销**实时更新**；全员卡片统计所有参与组，
   定向卡片只统计目标组。「重置」收回卡片的同时清空全部回执，新一轮演练从零统计。
4. **处置答复**：主持人在每张已揭示卡片下方看到「答复 n/m」、逐组提交徽标
   （✓ v版本号 / 未提交）与各组答复正文，随参与者保存**实时更新**；定向卡只统计
   目标组，全员卡覆盖现有全部参与组。卡片标题栏的「🔓 答复开放 / 🔒 答复已锁定」
   按钮可逐卡锁定或重新开放答复（未揭示的卡片也可预先锁定）；锁定后参与者只读。
   「重置」清空全部答复并解除全部锁定。
5. **回执门槛（可选）**：添加卡片时在「回执门槛」下拉选择一张前置卡片，本卡到触发
   时刻后不立即揭示，而是等前置卡片的目标参与组**全部回执**才揭示；可同时填写
   **超时秒数**（虚拟时钟，自本卡触发时刻起算），超时仍未集齐则标记为「超时揭示」并继续。
   主持人在卡片上看到门槛状态：**等待回执**（含未回执组名单与超时点）/ **已解锁** /
   **超时揭示**，随回执与撤销实时翻转；暂停期间超时计时冻结，重置后门槛随回执清零
   重新等待。被依赖的前置卡片不可删除（需先删除依赖它的卡片）。
6. **观察席分享（可选）**：主持人在控制台「观察席分享」勾选 1～3 个参与组、填写
   5～120 分钟有效期 →「生成观察链接」→ 复制链接发给观察员。观察员打开链接即进入
   只读观察席，实时看到已揭示的全员卡片与所选组卡片及演练时钟。分享列表实时显示
   每条链接的状态（有效 / 已过期 / 已撤销）与剩余时间，可随时「撤销」；
   到期或撤销的瞬间在线观察者即被断开，链接永久失效。
7. **现场决策投票（任意时刻）**：控制台「发起现场决策投票」填写问题与 2～4 个选项
   （选项顺序即平票决胜顺序）、勾选参与组、填写截止虚拟秒 →「发起投票」。被勾选的
   参与组在页面下方「现场决策投票」面板看到投票，截止前点选项即可投票或改投（每组
   只计一票，同组任一人操作全组生效）；**结算前只能看到本组的选择**，暂停期间截止
   计时冻结、仍可改投。到虚拟截止点后服务端在状态锁内一次性自动结算（最高票获胜，
   平票按选项顺序），主持人卡片实时显示逐组选票与汇总，参与者**结算后**才看到获胜
   选项与票数；观察者看不到任何投票。主持人发起时若截止点不晚于当前虚拟时钟会被
   拒绝（`400`）；重置时未结算投票作废，已结算结果按轮次保留并在主持人列表标记
   所属历史轮。
8. **复盘锚点（任意时刻）**：控制台「复盘锚点」填写标题与可选备注 →「记录锚点」。
   服务端在状态锁内把锚点绑定到当前轮次、虚拟毫秒与当时事件水位；暂停期间记录的锚点
   虚拟时间停在冻结值。锚点列表实时显示轮次、`T+虚拟时间` 与绑定水位，可随时「修改备注」
   或「删除」；重置后旧锚点保留，标记为历史轮、归属原轮次。参与者与观察者看不到任何锚点。
9. **复盘包导出（任意时刻）**：主持人在控制台点击「**导出复盘包（ZIP）**」，浏览器即下载
   `review-<演练名>-<时间戳>.zip`（文件名自动去除特殊字符）。开始前导出得到的是空编排包、
   运行中导出得到的是点击瞬间事件水位的快照，均可正常打开。解压后**双击 `replay.html`**
   即可离线回放（无需启动服务、无需联网）：顶部选择演练轮次并拖动「虚拟时间」滑块
   （或点「播放」按倍速走一遍），页面还原该时刻的已揭示卡片、各组回执、答复及其版本轨迹；
   「复盘锚点」面板按轮次列出包内锚点，**点击锚点**滑块即跳到其绑定虚拟时间，并仅重放至
   锚点水位以还原同一虚拟时刻内的精确状态（拖滑块 / 切轮 / 播放可退出锚点截断）；
   下方「时钟动作轨迹」列出开始/暂停/继续/重置与对应虚拟时间，「事件流」表高亮恰好
   发生在当前虚拟时刻（锚点模式下高亮水位边界）的事件，同一时刻按事件 ID 升序。
   包内 `data.json` 为同一份脱敏原始数据，可用于二次分析。

## 同步协议说明

- 所有状态变更（分组增删改、卡片增删、揭示、回执、答复、答复锁定、门槛状态、
  复盘锚点、投票创建/投票/结算/作废、时钟动作）都会落库为**单调递增事件**并广播。
- 房间码是主持人凭证（全量视野）；组加入码是参与者凭证（仅全员 + 本组视野）。
  快照与每条增量事件都在服务端按视野过滤，参与者不会收到他组卡片，也拿不到房间码。
- WebSocket 连接建立时客户端携带 `last_event_id`；服务端在锁内先下发权威快照
  （含事件水位），再广播后续增量事件；客户端丢弃 `id <= 水位` 的事件，因此刷新、
  重连后状态不回退，也不会混入他组内容。
- 参与组被删除后其加入码立即失效，仍在连接的该组参与者会被服务端主动断开。
- 观察凭证是第三种连接凭证（随机 128 位，与房间码/加入码不同命名空间）：观察者
  连接 `/ws/observe/{token}`，快照与增量按「已揭示 ∩（全员 ∪ 所选组）」过滤，
  不下发未揭示卡、房间码、组加入码与回执明细；`share_*` 管理事件仅主持人可见。
  撤销或到期时服务端按凭证断开全部在线观察者（关闭码 4403），凭证此后 REST 返回
  `410`、WS 拒绝接入，刷新重连不可恢复；到期扫描由后台 tick 完成并落库标记，
  服务重启后不会重复广播，凭证状态也不会丢。
- 服务重启时，处于运行中的房间会被安全冻结为「已暂停」，已流逝时间结算保留。

## 回执 API 与事件

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `POST` | `/api/join/{组加入码}/cards/{card_id}/receipt` | 标记「已收到」，幂等；未揭示卡片返回 `409`，本组不可见卡片返回 `404` |
| `DELETE` | `/api/join/{组加入码}/cards/{card_id}/receipt` | 撤销回执，幂等 |

- 回执变化以 `receipt_updated` 事件广播：`{card_id, group_id, acked}`；
  按视野过滤——主持人全收，参与者只收到本组的回执事件（同组多个在线成员自动同步）。
- 快照中的回执视图同样按视野区分：主持人每张卡片带
  `receipts: {expected: [...], acked: [...]}`（expected = 全员卡的所有参与组 / 定向卡的目标组），
  参与者只带 `my_receipt: true/false`，看不到他组的回执情况。
- 回执存于 `receipts` 表，`UNIQUE(card_id, group_id)` 保证同组仅一条；
  删除卡片/参与组时级联清理，「重置」清空全房间回执。

## 回执门槛 API 与事件

`POST /api/rooms/{房间码}/cards` 的请求体新增两个可选字段：

| 字段 | 说明 |
| --- | --- |
| `depends_on_card_id` | 前置卡片 id（须为本房间已有卡片）；前置卡片对其目标参与组全部集齐回执后本卡才揭示。缺省 = 无门槛 |
| `gate_timeout_seconds` | 虚拟时钟超时秒数（1～86400，自本卡 `trigger_seconds` 时刻起算）；超时仍未集齐回执则标记为超时揭示。必须搭配 `depends_on_card_id`，单独提供返回 `400` |

- 前置卡片不存在返回 `404`；`gate_timeout_seconds` 为 0 或越界返回 `422`。
  依赖边只能指向更早创建的卡片，依赖图天然无环，也支持链式门槛（C 等 B、B 等 A）。
- 删除被依赖的前置卡片返回 `409`（需先删除依赖它的卡片）。
- 门槛状态以 `gate_updated` 事件广播，**仅主持人可见**（参与者/观察者收不到，
  避免泄露编排依赖）：`{card_id, gate}`，其中 `gate = {depends_on_card_id,
  depends_on_seq, gate_timeout_seconds, state, pending_groups}`，
  `state ∈ waiting | unlocked | timeout`，`pending_groups` 为尚未回执的前置目标组。
  触发时机：创建门槛卡、前置卡回执变化、参与组增删、重置、超时揭示。
- 主持人快照中每张门槛卡附带同样的 `gate` 对象；参与者与观察者快照不含任何门槛字段。
- 门槛判定完全由持久化状态推导：`cards.depends_on_card_id / gate_timeout_seconds /
  timed_out` 三列 + `receipts` 表。暂停/继续、断线重连、服务重启后状态自然保持；
  「重置」清回执并复位 `timed_out`，门槛回到等待（编排配置保留）。
- 旧库启动时自动迁移：`cards` 表补齐上述三列，既有卡片一律视为无门槛。
- 超时揭示的卡片在主持人视图标记「超时揭示」；对参与者而言就是一张普通的已揭示卡片。

## 处置答复 API 与事件

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `PUT` | `/api/join/{组加入码}/cards/{card_id}/answer` | 提交/修改本组答复：`{body, revision}`；`revision` 须等于服务端当前版本（尚无答复时传 `0`）。未揭示卡片、已锁定卡片均返回 `409`；版本过期返回 `409` 且 `detail.answer` 携带最新答复 |
| `POST` | `/api/rooms/{房间码}/cards/{card_id}/answers/lock` | 主持人锁定该卡答复（幂等）：参与者只读，写入返回 `409`（`detail.error = answers_locked`） |
| `POST` | `/api/rooms/{房间码}/cards/{card_id}/answers/unlock` | 主持人重新开放该卡答复（幂等） |

- 答复变化以 `answer_updated` 事件广播：`{card_id, group_id, body, revision, updated_at}`；
  **含正文，按视野过滤**——主持人全收，参与者只收本组的答复事件（同组多个在线成员自动同步），
  观察者收不到。锁定变化以 `answer_lock_updated` 事件广播：`{card_id, group_id, answers_locked}`，
  按卡片视野下发（主持人全收，参与者只收本组可见卡片）。
- 快照中的答复视图按视野区分：主持人每张卡片带
  `answers: {expected: [...], submitted: [{group_id, body, revision, updated_at}, ...]}`
  （expected 口径与回执一致：全员卡 = 所有参与组 / 定向卡 = 目标组）；
  参与者只带 `my_answer: {body, revision} | null`，看不到他组正文；观察者不带任何答复字段。
  卡片公共字段 `answers_locked` 对所有角色可见（仅锁定状态，不含答复内容）。
- 答复存于 `answers` 表，`UNIQUE(card_id, group_id)` 保证同组仅一份，`revision` 每次修改 +1；
  删除卡片/参与组时级联清理，「重置」清空全房间答复并复位全部 `answers_locked`。
- 旧库启动时自动迁移：`cards` 表补 `answers_locked` 列（既有卡片一律未锁定），并新建 `answers` 表。

## 观察席分享 API 与事件

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `POST` | `/api/rooms/{房间码}/shares` | 创建分享：`{group_ids: [1~3 个组 id], minutes: 5~120}`；返回含随机 `token` 的分享对象 |
| `DELETE` | `/api/rooms/{房间码}/shares/{token}` | 撤销分享，幂等；在线观察者立即被断开 |
| `GET` | `/api/observe/{token}` | 观察者只读快照；凭证不存在 `404`，已撤销/已到期 `410` |
| `WS` | `/ws/observe/{token}?last_event_id=` | 观察者实时通道：先快照后增量，按观察视野过滤；失效时以 4403 关闭 |

- 观察链接格式：`{origin}/#/observe/{token}`，主持人控制台一键复制。
- 分享变化以 `share_created` / `share_revoked` / `share_expired` 事件广播，**仅主持人可见**
  （载荷含观察凭证，参与者与观察者都收不到）。
- 观察者快照中：`room` 不含房间码、`groups` 不含组加入码（仅所选组的 id 与名称）、
  `cards` 只含已揭示卡片且不带任何回执字段。
- 分享存于 `observer_shares` 表（凭证、所选组、到期时刻、撤销与到期标记），
  随 SQLite 持久化，服务重启后有效分享继续可用、失效分享继续失效。

## 现场决策投票 API 与事件

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `POST` | `/api/rooms/{房间码}/polls` | 主持人发起投票：`{question, options[2~4], group_ids[≥1], deadline_seconds[1~86400]}`；`201` 返回主持人全量投票对象。选项空/重复、组不属于本房间返回 `400/404`；截止虚拟秒不晚于当前虚拟时钟返回 `400` |
| `PUT` | `/api/join/{组加入码}/polls/{poll_id}/vote` | 指定组投票/改投：`{option_id}`；每组只计一票（改投原地更新，返回 `changed`）。非白名单组、旧轮次投票 `404`；已结算/已作废 `409`；已到截止点（等待 tick 结算的窄窗口）`409`；选项不属于本投票 `404` |

- **快照（主持人）**：`polls` 数组含**全部轮次**投票，每条为
  `{id, question, round, deadline_ms, status, group_ids, options:[{id,seq,text}],
  votes:[{group_id,option_id}], tallies:[{option_id,count}], winner_option_id,
  settled_at_ms}`；`status ∈ open | settled | voided`。
- **快照（参与者）**：只含**当前轮次、白名单包含本组**的投票。`open` 时为
  `{id, question, round, deadline_ms, status, options, my_option_id}`——
  不含票数、获胜者与他组选择；`settled` 时额外带 `winner_option_id /
  settled_at_ms / tallies`（结果公开，但仍无逐组 `votes`）。
- **观察者快照与任何 `poll_*` 事件均不下发**（投票对观察者完全不可见）。
- **事件**：
  - `poll_created`：主持人收全量投票对象；白名单参与组收**脱敏 open 载荷**
    （无任何选票字段），非白名单组与观察者收不到。
  - `poll_vote_updated`：`{poll_id, group_id, option_id}`；主持人额外收
    `poll` 全量对象（逐组选票），**只有投票的本组**参与者收脱敏三字段，
    同白名单的他组与观察者收不到。
  - `poll_settled`：tick 在 `state_lock` 内一次性结算后广播。主持人收全量
    （含 `winner_option_id / tallies / votes / settled_at_ms`）；白名单参与组
    由服务端按组定向投递脱敏结果载荷（本组已投选项 + 获胜结果与汇总，无逐组
    明细）；观察者收不到。断线重连以快照为准，不会因错过事件而看不到结果。
  - `poll_voided`：重置作废未结算投票时逐条广播，**仅主持人可见**
    （`{id, round, status:'voided'}`）；参与者在 `reset` 事件时清空本轮投票。
- **结算口径**：`polls.status` 由 tick 从 `open` 原子置为 `settled` 并写回
  `winner_option_id / settled_at_ms`，每条投票只结算一次（重复 tick、服务重启
  均不重复结算）；票数只统计**本轮** `poll_votes`，最高票获胜，平票按
  `poll_options.seq`（创建顺序）取最早者，全员零票取第一个选项。
- **持久化与轮次**：投票存于 `polls / poll_options / poll_groups / poll_votes`
  四表（`UNIQUE(poll_id, group_id)` 保证每组一票），均随 SQLite 持久化；
  截止是相对本轮开始的**虚拟毫秒**，暂停冻结、重启先冻结 running 房间。
  重置删除未结算投票的选票并置 `voided`，已结算行与其选票按 `round` 保留；
  删除参与组/房间经外键级联清理白名单、选票与投票。
- 旧库启动时自动迁移：投票四表为全新表，由 `CREATE TABLE IF NOT EXISTS`
  直接补齐（含 `idx_polls_room` 等索引），既有演练视为没有任何投票。
- 投票事件**不进入复盘包导出**（与观察分享事件同类，整类不在导出白名单）。

## 复盘锚点 API 与事件

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `POST` | `/api/rooms/{房间码}/anchors` | 记录锚点：`{title, note?}`；任意房间状态可记，`201` 返回含绑定信息的锚点 |
| `PATCH` | `/api/rooms/{房间码}/anchors/{id}` | 修改备注：`{note}`（标题与绑定的轮次/时间/水位不可变）；不存在 `404` |
| `DELETE` | `/api/rooms/{房间码}/anchors/{id}` | 删除锚点；不存在 `404` |

- **锁内绑定次序**（POST 全程在 `state_lock` 临界区）：① 读当前轮次
  `COUNT(reset 事件)`；② 读当时事件水位 `MAX(events.id)`（锚点自身事件尚未落库）；
  ③ 读当前虚拟毫秒 `room_elapsed_ms`（running 叠加当前运行段，paused/idle 为冻结值，
  暂停期间绝不推进）；④ 插入 `anchors` 行；⑤ 落库 `anchor_created` 事件（其 id 恰为
  绑定水位 + 1）并把该 id 回填到行内 `created_event_id`。
- 锚点变化以 `anchor_created` / `anchor_updated` / `anchor_deleted` 事件广播，
  **仅主持人可见**：`event_visible` 对一切 `anchor_*` 类型向参与者与观察者返回 false，
  且仅主持人快照顶层带 `anchors` 数组（观察者/参与者快照无该字段）。
- **重置保留**：`reset` 只清揭示/回执/答复与时钟，不删 `anchors`；旧锚点以行内
  `round` 归属原轮次，新一轮锚点 `round` 递增。快照额外带房间级 `round` 字段
  （= 当前轮次，非敏感，三种角色均下发，供前端标记历史锚点）。
- **持久化**：锚点存于 `anchors` 表（`title/note/round/vtime_ms/event_id/
  created_event_id/created_at/updated_at`），修改备注只改 `note` 与 `updated_at`，
  绑定字段永不变；刷新、断线重连、服务重启后状态不丢。
- 旧库启动时自动迁移：`anchors` 为全新表，由 `CREATE TABLE IF NOT EXISTS` 直接补齐，
  既有演练视为没有任何锚点；同时补齐更早版本 `cards` 表可能缺失的
  `revealed/revealed_at_ms` 等历史列（供 SCHEMA 索引建立）。

## 复盘包导出 API 与包结构

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/rooms/{房间码}/review.zip` | 主持人导出复盘 ZIP；房间码错误返回 `404`。响应头 `Content-Disposition: attachment; filename*=UTF-8''review-…zip` |

- **水位一致性**：处理在 `state_lock` 内完成（与全部状态写操作同一把锁）。进入临界区后先取
  `high_water = MAX(events.id)`，之后采集的事件一律 `id <= high_water`；临界区内不会插入
  新事件，锁释放后产生的事件 ID 必然更大，因此**生成期间到达的新事件不会混入**。
  运行中房间的虚拟时钟值按读取瞬间的运行段结算（与快照同口径）。
- **导出入口**：主持人控制台「导出复盘包（ZIP）」按钮（仅主持人可见；参与者与观察者无此入口）。
- **ZIP 内容**（`app/export.py` 组装，`ZIP_DEFLATED` 压缩）：

  | 文件 | 说明 |
  | --- | --- |
  | `replay.html` | 单文件离线回放页，数据已内联、零外链、无第三方依赖；`file://` 双击即可打开 |
  | `data.json` | 同一份复盘原始数据（JSON，缩进 2 格），便于二次分析 |
  | `README.txt` | 包内使用说明 |

- **`data.json` 顶层字段**：

  | 字段 | 内容 |
  | --- | --- |
  | `high_water_event_id` / `generated_at` | 导出水位与生成时刻 |
  | `room` / `rounds` | 房间（无房间码）与各演练轮次（是否被重置结束、轮末虚拟毫秒） |
  | `orchestration` | 房间编排：参与组（仅 id/名称）、全部卡片（触发秒数、目标、门槛配置、锁定态） |
  | `revealed_cards` | 水位时刻已揭示卡片（含揭示虚拟时间、是否超时揭示） |
  | `receipts` | 水位时刻各卡各组回执 |
  | `answers` | 水位时刻各卡各组最新答复（正文 + 当前版本号） |
  | `answer_versions` | **答复版本轨迹**：重放 `answer_updated` 事件得到的全部历史版本（含正文、版本号、事件 ID） |
  | `anchors` | **复盘锚点**：仅 `created_event_id <= 导出水位` 者（导出前已存在），按 `(轮次, 虚拟毫秒, id)` 排序；每条带绑定 `round` / `vtime_ms` / `event_id`（回放截断水位）与最新备注 |
  | `clock_actions` | **时钟动作**：开始/暂停/继续/重置，附所属轮次与虚拟时间 |
  | `events` | 脱敏事件时间线：每条带 `round` 与推导的 `vtime_ms`，整体按 `(轮次, 虚拟时间, 事件 ID)` 排序 |

- **脱敏保证**：房间码不出现在任何事件载荷中；组加入码在导出时从 `group_added` 载荷移除
  （编排只保留组 id 与名称）；观察 token 仅存在于 `share_created/share_revoked/share_expired`
  事件，这些事件类型在白名单之外、**整类剔除**，分享表本身也不读取。复盘锚点是主持人专属
  数据，`anchor_created/anchor_updated/anchor_deleted` 同样在事件白名单之外、**整类不进
  事件流**，锚点改由独立的 `anchors` 字段导出（已按导出水位截断）。
- **离线回放**：`replay.html` 不发起任何网络请求。卡片/参与组等持久编排跨重置保留（纯事件重放），
  揭示、回执、答复按轮次隔离；「重置」开启新一轮，滑块按轮切换。同一虚拟时刻的事件在事件流表中
  按事件 ID 升序展示，并高亮恰好落在当前虚拟时间的行。「复盘锚点」面板按轮次分组列出
  `anchors`：点击锚点 = 切到其轮次 + 滑块置为绑定 `vtime_ms` + 所有状态推导（编排、揭示、
  回执、答复版本、时钟动作、事件流）统一只消费 `id <= anchor.event_id` 的事件——即使另一事件
  与锚点处在**同一虚拟毫秒**，只要 ID 更晚也不计入，精确还原锚点时刻状态。空演练（事件水位 0）
  同样生成可打开的回放页。
